# CollegeShine merged project bug-fix notes (2026-10-10)

## Fixes applied
- Removed server-side hardcoded fallback blog records. `/api/blogs`, `/api/blogs/:slug`, and server-rendered `/blog/:slug/` pages use the MySQL `blogs` table only.
- Fixed blog API error handling so query parameters are not referenced outside their scope and database errors return HTTP 500 JSON rather than fake blog records.
- Fixed college data parsing to use the existing `colleges.index_json` and `colleges.detail_json` columns.
- Fixed college directory and taxonomy queries to stop selecting nonexistent `type`, `image`, and `data` columns; the current schema stores directory metadata in JSON columns.
- Removed the frontend local blog fallback, so a failed API no longer silently displays hardcoded articles.
- Preserved the existing site source, routes, college data assets, SEO files and project structure.

## Required setup
1. Copy `server/.env.example` to `server/.env` (or use the root `.env` only if you intentionally change the server's dotenv path).
2. Fill in the actual Hostinger MySQL host, database, username, and password. Do not commit `.env` to Git.
3. In Hostinger, ensure the database user has permissions on the target database and remote MySQL access is permitted for the machine running the app. A MySQL `Access denied` error is a credentials/permissions/allowlist issue and cannot be repaired by changing React code.
4. Run `npm install`, then `npm run build`, then `npm run server`.
5. Test `/api/health`, `/api/blogs`, and `/api/colleges?limit=5`.
6. Set `VITE_NOINDEX_ALL=false` for the final production domain after verifying that it is `collegeshine.com`. The server still sends noindex on temporary/non-production hosts by design.
